# 8.2 — Build de Windows (hecho desde Linux)

> Fase 8. Depende de 7.1 (plantillas de exportación instaladas y preset de Linux funcionando).

## 1. Objetivo y «Hecho cuando»

**Objetivo:** un `gamemolde.exe` hecho en la máquina Linux con el mismo proyecto.

**Hecho cuando:**
- `build/windows/gamemolde.exe` existe y, copiado solo a una carpeta de una máquina Windows, imprime `AUTOPRUEBA: TODO BIEN`.
- El `.glb` de esa autoprueba, llevado a Linux, pasa `probar_glb.gd` y es **idéntico en geometría** al que escribe el build de Linux (ver §6).

## 2. Nivel de modelo

**Medio.** El preset se crea desde el editor; la dificultad está en que la prueba se reparte entre dos máquinas.

## 3. Contexto mínimo

- `ruta/pasos/7.1_builds_linux.md`, entero (este paso es su gemelo).
- `godot/export_presets.cfg`.
- `PLATAFORMAS.md` §1 y §4.

## 4. Archivos

- **Se toca:** `godot/export_presets.cfg` (preset nuevo «Windows», desde el editor).
- **Se crea:** `pruebas/fase_8/probar_build_windows.sh` (parte de Linux) y `pruebas/fase_8/autoprueba.bat` (parte de Windows).
- **No se toca:** código del núcleo ni de la interfaz. Si Windows necesita un cambio de código, es otro paso con su propuesta.

## 5. Diseño

1. **Preset «Windows»** (el responsable, en Proyecto → Exportar → Añadir → Windows Desktop):
   - Arquitectura `x86_64`. «Incrustar PCK»: activado. Mismos filtros que Linux (`datos/*, *.txt`).
   - Ruta: `../build/windows/gamemolde.exe`.
   - «Exportar con consola de depuración» (*Debug → Export Console Wrapper*): **activado**. Genera además `gamemolde.console.exe`, el único que imprime en la terminal. Motivo: sin él no se puede leer `AUTOPRUEBA: …` en Windows.
   - Icono, nombre del producto y versión del archivo: Godot los escribe en el `.exe` con la herramienta `rcedit` (pide Wine en Linux). **No se configura en este paso:** el `.exe` sale con el icono de Godot. Se apunta como mejora en el 8.4.
   - Firma de código: desactivada (D15).
2. **Exportar** (`pruebas/fase_8/probar_build_windows.sh`):
   ```sh
   #!/bin/sh
   # 8.2: exporta el build de Windows desde Linux. La autoprueba se lanza después en Windows con autoprueba.bat.
   # Uso: pruebas/fase_8/probar_build_windows.sh 2>&1 | grep -E 'RESULTADO|MEDIDA|ERROR'
   set -e
   root=$(cd "$(dirname "$0")/../.." && pwd)
   mkdir -p "$root/build/windows"
   (ulimit -v 4000000; timeout 600 godot --headless --path "$root/godot" --export-release "Windows" "$root/build/windows/gamemolde.exe")
   for f in gamemolde.exe gamemolde.console.exe; do
     test -s "$root/build/windows/$f" || { echo "ERROR: falta $f"; exit 1; }
     echo "MEDIDA $f (bytes): $(stat -c %s "$root/build/windows/$f")"
   done
   echo "RESULTADO build de Windows creado"
   ```
3. **Autoprueba en Windows** (`pruebas/fase_8/autoprueba.bat`, se copia junto al `.exe`):
   ```bat
   @echo off
   rem 8.2: lanza la autoprueba del build y deja el resultado en autoprueba.txt
   gamemolde.console.exe --headless -- --autoprueba > autoprueba.txt 2>&1
   echo Codigo de salida: %ERRORLEVEL% >> autoprueba.txt
   type autoprueba.txt | findstr /C:"AUTOPRUEBA" /C:"Codigo"
   ```
4. **Traer el resultado:** el `.glb` y el `.tres` están en `%APPDATA%\Godot\app_userdata\GameMolde\`. Copiarlos a la máquina Linux.
5. **Comparar con el de Linux:** `comparar_glb.gd` (ya existe en `pruebas/godot/`; leer su cabecera para los argumentos) entre el `.glb` de la autoprueba de Linux y el de Windows.

## 6. Prueba

| Comprobación | Límite |
| --- | --- |
| `autoprueba.txt` | Contiene `AUTOPRUEBA: TODO BIEN` y `Codigo de salida: 0` |
| `.glb` de Windows con `probar_glb.gd` | `TODO BIEN` |
| `comparar_glb.gd` entre el de Linux y el de Windows: posiciones de vértices | Diferencia máxima < 0,001 mm (PROVISIONAL: lo esperado es 0; las dos máquinas usan el mismo cálculo en CPU) |
| Mismo número de vértices, triángulos y huesos | Igual |
| Carpeta de la prueba en Windows | Solo `gamemolde.exe`, `gamemolde.console.exe` y `autoprueba.bat` |

**Que la prueba detecta el fallo:** exportar una vez sin el filtro `datos/*` → `AUTOPRUEBA: FALLO` y código de salida 1.

## 7. Trampas conocidas

- Godot exporta para Windows desde Linux sin herramientas extra; solo los metadatos del `.exe` (icono, versión) piden `rcedit` + Wine. Si el exportador avisa de `rcedit`, es un aviso, no un error.
- Windows SmartScreen y el antivirus pueden bloquear un `.exe` sin firma al primer arranque («Windows protegió su PC» → «Más información» → «Ejecutar de todas formas»). Se documenta en el 8.4.
- Forward+ en Windows usa Vulkan por defecto; Godot puede usar Direct3D 12 si se configura (`rendering/rendering_device/driver.windows`). **No cambiarlo aquí**: el renderizador se decide en el 5.13 (A7).
- Los nombres de archivo en `preload` deben coincidir en mayúsculas con el disco. Dentro del `.pck` se distinguen también en Windows: un error así aparece en el build aunque el proyecto funcionara en el editor de Windows.
- `%ERRORLEVEL%` de `gamemolde.exe` (sin consola) no es fiable desde un `.bat` porque el programa se separa de la terminal. Usar siempre `gamemolde.console.exe` en pruebas.
- Las credenciales no van en `export_presets.cfg` (ver trampa del 7.1).

## 8. Juicio visual

El responsable abre `gamemolde.exe` en Windows. Preguntas: ¿se ve igual que en Linux (color, contorno, letra)? ¿La ventana se abre a un tamaño cómodo con la escala de pantalla de Windows al 125 % o 150 %?

## 9. Si te atascas

- Si la autoprueba pasa en Linux y falla en Windows: copia el contenido completo de `autoprueba.txt` y **para**. No adivines.
- Si `comparar_glb.gd` da una diferencia mayor que el límite: no toques el límite; da la medida y qué vértices difieren más.
