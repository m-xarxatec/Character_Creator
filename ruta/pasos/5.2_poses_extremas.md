## 5. Diseño

**Formato de una pose** (el mismo que usará el proyecto compartido, `ARQUITECTURA.md` §1, pero con eje y ángulo en vez de cuaternión, para poder escribirlo a mano):

```json
{
  "brazos_arriba": {
    "nombre": "Brazos arriba",
    "cadera": [0, 0, 0],
    "huesos": {
      "LeftUpperArm":  [0, 0, 1,  80],
      "RightUpperArm": [0, 0, 1, -80]
    }
  },
  "sentadilla": {
    "nombre": "Sentadilla",
    "cadera": [0, -0.50, 0],
    "huesos": {
      "LeftUpperLeg":  [1, 0, 0, -95], "RightUpperLeg": [1, 0, 0, -95],
      "LeftLowerLeg":  [1, 0, 0,  25], "RightLowerLeg": [1, 0, 0,  25],
      "LeftFoot":      [1, 0, 0,   0], "RightFoot":     [1, 0, 0,   0],
      "Spine":         [1, 0, 0,  20]
    }
  },
  "giro_de_tronco": {
    "nombre": "Giro de tronco",
    "cadera": [0, 0, 0],
    "huesos": {"Spine": [0, 1, 0, 15], "Chest": [0, 1, 0, 30], "UpperChest": [0, 1, 0, 45]}
  }
}
```

- Cada hueso: `[eje x, eje y, eje z, grados]`. Es el giro **en el mundo respecto a la pose T**, no respecto al padre. Un hueso que no aparece sigue a su padre.
- `cadera`: desplazamiento de `Hips` en **fracción de su altura en reposo** (−0,50 = baja un 50 %; ajustar hasta que los pies queden en el suelo).
- Por qué esos signos: un giro positivo alrededor de +Z lleva +X hacia +Y (sube el brazo izquierdo); alrededor de +X, un giro negativo lleva −Y hacia +Z (el muslo va hacia delante). `LeftFoot` con 0° se escribe a propósito: sin él, el pie heredaría los 25° de la pierna.
- Los valores son un **punto de partida**: el responsable los ajusta mirando las capturas.

```gdscript
# godot/app/bone_test.gd — añadidos
const POSES_FILE := "poses/extremas.json"
var poses: Dictionary                       # leído en setup()
func pose_names() -> PackedStringArray
func set_pose(id: String) -> bool           # para la animación y pone la pose; false si no existe
static func to_deltas(bones: Dictionary) -> Dictionary     # {hueso: [x,y,z,grados]} → {hueso: Quaternion}
```

1. `setup()` lee el JSON (ruta relativa al script, con `get_script().resource_path.get_base_dir()`).
2. `to_deltas`: por cada hueso, `Quaternion(Vector3(x, y, z).normalized(), deg_to_rad(grados))`.
3. `set_pose(id)`: `player.stop()`; `WorldPose.apply(target, to_deltas(pose["huesos"]))`; cadera: `target.set_bone_pose_position(hips, rest.origin + Vector3(pose["cadera"]) * altura_de_la_cadera_en_reposo)`, con `altura = target.get_bone_global_rest(hips).origin.y`.
4. `body_page`: un botón por pose, junto a los de las animaciones.

**Script de capturas compartido** (lo reutilizan 5.5, 5.8, 5.9, 5.12 y 5.13):

```
pruebas/godot/capturar_banco.gd   (extends SceneTree; necesita ventana)
Uso: godot --path godot -s ../pruebas/godot/capturar_banco.gd -- --salida=<carpeta> [--preset=<ruta .json>]
     [--variante=t|a] [--pose=<id>|--animacion=<nombre>@<0..1>] [--camara=frente|perfil|espalda|tres_cuartos|juego|<zona>]
```

- Monta la vista como `probar_animacion.gd` (SubViewport de tamaño fijo, misma luz y fondo en todas las capturas).
- `--camara=<zona>`: primeros planos con nombre: `hombro`, `codo`, `mano`, `rodilla`, `cadera`, `cuello`. Cada uno mira al hueso correspondiente desde 0,6 m.
- `--camara=juego`: unos 45° desde arriba, a distancia de juego (`GUIA_ESTILO.md` §6).
- Sin `--camara`: guarda una hoja con frente, perfil, espalda y tres cuartos.
- Imprime `GUARDADO <ruta>` por cada imagen.

## 6. Prueba

`pruebas/godot/probar_poses.gd`, sin ventana, con `--path godot`:

| Comprobación | Límite |
| --- | --- |
| El JSON se lee y tiene las 3 poses | exacto |
| Todos los huesos nombrados existen en el esqueleto horneado | exacto |
| «Brazos arriba»: ángulo entre la dirección hombro→codo y la de reposo | 80° ± 0,1° en cada brazo |
| «Sentadilla»: la cadera baja el 50 % de su altura; el pie conserva su orientación de reposo | < 0,1 mm y < 0,1° |
| «Giro de tronco»: `UpperChest` gira 45° alrededor de Y; la cabeza, también 45° | ± 0,1° |
| Con `height` a 0 y a 1, las mismas comprobaciones | Mismos límites |
| Poner una pose y después `stop()` | Reposo exacto (0,001°) |

Límites PROVISIONALES (D26).

**Que la prueba detecta el fallo:** en `to_deltas`, olvidar `deg_to_rad`. Todas las filas de ángulo deben fallar. Devolverlo.

## 7. Trampas conocidas

- En el JSON los números son `float` y las listas son `Array`: `Vector3(a[0], a[1], a[2])`.
- El esqueleto de la vista de prueba es el horneado: reposa en pose T. Estas poses **no** valen sobre el maniquí vivo (pose A).
- Con la pose puesta no debe estar copiándose una animación: `set_pose` para el reproductor primero.
- Las capturas van a la carpeta de `--salida`; nunca a la de otra prueba (regla de `CLAUDE.md`).
- `capturar_banco.gd` usa recursos del proyecto `godot/`: se lanza con `--path godot`.
