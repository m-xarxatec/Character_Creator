# 8.1 — Pasar las pruebas sin ventana en Windows

> Fase 8 (Windows), primer paso. Depende de A1 y A2 y de la decisión D16 (instalar Godot 4.7.2 en la máquina Windows).
> Si D16 = b (no instalar), este paso **no se hace**: se salta al 8.2 y Windows se prueba solo con la autoprueba del build.

## 1. Objetivo y «Hecho cuando»

**Objetivo:** saber, con datos, qué se comporta distinto en Windows antes de hacer el build.

**Hecho cuando:**
- Todas las pruebas sin ventana de `pruebas/godot/` se han lanzado en Windows y hay una tabla «prueba → resultado en Linux → resultado en Windows».
- Cada diferencia tiene una causa escrita (ruta, final de línea, precisión numérica, shell) y una propuesta de arreglo. No se arregla nada del núcleo en este paso.

## 2. Nivel de modelo

**Simple** para lanzar y tabular. **Medio** si aparece una diferencia numérica: explicar su causa pide entender la prueba.

## 3. Contexto mínimo

- `PLATAFORMAS.md` §1.
- `GUIA_MODELOS.md` §5 (el bucle que lanza todas las pruebas).
- La cabecera (5–10 líneas) de cada `pruebas/godot/probar_*.gd`, para saber sus argumentos.

## 4. Archivos

- **Se crea:** `pruebas/pasar_sin_ventana.sh` (si no lo creó ya otro paso) y `ruta/medidas/8.1_windows.md` con la tabla.
- **No se toca:** ninguna prueba, ningún límite, nada de `godot/`.

## 5. Diseño

1. **Comprobar el entorno** (Git Bash):
   - `godot --version` → debe empezar por `4.7.2.stable`. En Windows el ejecutable de consola se llama `Godot_v4.7.2-stable_win64_console.exe`; el responsable crea un alias o lo pone en el PATH como `godot`.
   - `git config core.autocrlf` y `git ls-files --eol godot/datos/humana | head` → los archivos de `datos/` deben salir `w/lf` (A1).
   - `git lfs ls-files | head -3` → `cuerpo.glb` listado; `ls -l godot/datos/humana/cuerpo.glb` → unos 15,9 MB, no 130 bytes.
2. **Importar el proyecto una vez:** `timeout 300 godot --headless --path godot --import` y lo mismo con `--path pruebas/godot`.
3. **Lanzar las pruebas.** `pruebas/pasar_sin_ventana.sh`:
   ```sh
   #!/bin/sh
   # Lanza todas las pruebas de Godot que no necesitan ventana y resume una línea por prueba.
   # Uso: pruebas/pasar_sin_ventana.sh [raíz del repositorio]   (en Windows: desde Git Bash)
   root=${1:-$(cd "$(dirname "$0")/.." && pwd)}
   lim="ulimit -v 4000000;"; case "$(uname -s)" in MINGW*|MSYS*) lim="";; esac   # en Git Bash, ulimit -v no limita
   WINDOWED="probar_animacion probar_cara_anime probar_estilo probar_normales_cara probar_prenda probar_prenda_exportada probar_proporciones probar_reajuste_esqueleto probar_rendimiento probar_valores_estilo"
   for f in "$root"/pruebas/godot/probar_*.gd; do
     n=$(basename "$f" .gd)
     case " $WINDOWED " in *" $n "*) echo "$n: SALTADA (necesita ventana)"; continue;; esac
     out=$(sh -c "$lim timeout 300 godot --headless --path '$root/pruebas/godot' -s $n.gd -- '$root' 2>&1" | grep -E 'FALLO|RESULTADO|ERROR' | tail -3 | tr '\n' ' ')
     echo "$n: $out"
   done
   ```
   **Importante:** no todas las pruebas reciben los mismos argumentos. Antes de fiarse del bucle, leer la cabecera de cada prueba (línea «Uso:») y ajustar el argumento si pide otra cosa (por ejemplo, la ruta a `cuerpo.glb`). Las que pidan argumentos distintos se lanzan a mano y se anotan igual.
4. **Lanzar lo mismo en Linux** (lo hace el responsable o está en el registro) y rellenar la tabla.
5. **Pruebas de Blender y scripts `.sh` de `pruebas/fase_3/`:** no se lanzan en Windows. Blender solo prepara `datos/` y eso se hace en Linux. Anotarlo en la tabla como «no aplica».
6. **Clasificar cada diferencia:**

| Tipo | Ejemplo | Qué se propone |
| --- | --- | --- |
| Ruta | La prueba monta una ruta con `/tmp` o supone `/home` | Usar `OS.get_user_data_dir()` o `user://` en la prueba |
| Final de línea | `sha256` distinto | A1 no está aplicado o el clon es anterior: volver a clonar |
| Numérica | Una medida cambia en el último decimal | Anotar las dos medidas. **No tocar el límite** (regla 9); si lo supera, propuesta con la medida real |
| Shell | `ulimit`, `mktemp`, `stat -c` | Solo afecta a los `.sh`; anotarlo |
| Tiempo | Una prueba tarda mucho más (antivirus) | Anotar el tiempo; subir el `timeout` solo en el comando, no en la prueba |

## 6. Prueba

Este paso **es** una prueba. Su resultado:

| Comprobación | Límite |
| --- | --- |
| Pruebas sin ventana lanzadas en Windows | Todas las de `pruebas/godot/` menos las 10 con ventana |
| Pruebas con el mismo resultado que en Linux | Se anota el número; el objetivo es todas |
| Diferencias sin causa escrita | 0 |

**Que la prueba detecta el fallo:** en una copia de trabajo, convertir `godot/datos/humana/manifiesto.json` a finales de línea CRLF (`unix2dos`) y lanzar `probar_carga`: debe fallar por el `sha256`. Deshacer con `git checkout -- <archivo>` (lo ejecuta el responsable).

## 7. Trampas conocidas

- `godot.exe` (sin `_console`) no escribe en la terminal en Windows: las pruebas parecen no imprimir nada. Usar el ejecutable de consola.
- En Git Bash, las rutas que empiezan por `/c/…` se convierten solas a `C:\…` al pasarlas a un programa de Windows; una ruta tras `--` puede convertirse mal. Si una prueba no encuentra un archivo, pasar la ruta como `C:/…`.
- `timeout` de Git Bash existe; `ulimit -v` no limita (**NO VERIFICADO** qué imprime). Por eso el script lo quita.
- El antivirus puede retrasar el primer arranque de Godot varios segundos: no es un fallo.
- `--headless` en Windows usa el controlador de vídeo «dummy», igual que en Linux: las pruebas con ventana siguen necesitando ventana.
