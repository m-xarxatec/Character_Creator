# 7.3 — Revisión de licencias y de `CREDITOS.md`

> Paso del MVP (Fase 7). Hacerlo **antes** del 7.4. Tiene dos subpasos: **7.3a** revisión (solo documentos) y **7.3b** diálogo «Licencias» dentro del programa.

## 1. Objetivo y «Hecho cuando»

**Objetivo:** que todo lo que se reparte (el repositorio y el build) lleve su licencia y su crédito, y que no haya nada que no se pueda repartir.

**Hecho cuando:**
- La lista de revisión del §5 está completa, con una línea «bien / mal / no aplica» por punto, entregada al responsable.
- El programa tiene un diálogo «Licencias» que muestra: la licencia MIT del programa, los créditos de `CREDITOS.md` y los avisos de Godot y de sus bibliotecas.
- `probar_licencias.gd` pasa.

## 2. Nivel de modelo

**Medio.** No es difícil, pero un error aquí es legal, no técnico. Un modelo simple puede hacer el 7.3b; el 7.3a necesita criterio para no dar por buena una licencia sin comprobarla. **El modelo no decide si una licencia vale: lista y pregunta.**

## 3. Contexto mínimo

- `CREDITOS.md`, `LICENSE`, `README.md` (sección Licencia), `CLAUDE.md` (regla 5).
- `IDEAS.md`: buscar con `grep -n -i 'licencia\|CC-BY' IDEAS.md`.
- `git ls-files | grep -v -E '^(pruebas/capturas|ruta)/'` (la lista de lo que se reparte).
- `godot/app/main.gd` (dónde se añade el botón).

## 4. Archivos

- **7.3a:** `CREDITOS.md` (filas que falten o sobren), `README.md` (sección de licencias, si el 7.2 no la dejó bien). Archivo nuevo `godot/datos/LICENCIA.txt` (texto CC0 corto que viaja con los datos).
- **7.3b:** nuevo `godot/app/licenses_dialog.gd`; `godot/app/main.gd` (un botón «Licencias» o entrada «Acerca de»); nueva prueba `pruebas/godot/probar_licencias.gd`.
- **No se toca:** `LICENSE` (salvo que el responsable pida cambiar el titular o el año), `godot/addons/creador/`.

## 5. Diseño

### 7.3a — Lista de revisión

Para cada punto, escribir el comando usado y el resultado.

1. **Cada archivo de terceros tiene fila en `CREDITOS.md`.** Listar binarios y datos: `git ls-files | grep -E '\.(glb|png|jpg|ttf|otf|woff2?|ogg|wav|hdr|exr|blend)$'`. Para cada uno: ¿es nuestro (lo genera un script del repositorio) o de terceros? Los de terceros, con fila.
2. **Cada fila de `CREDITOS.md` corresponde a algo que sigue en el repositorio.** Si ya no se usa, se propone quitar la fila.
3. **Licencias admitidas** (regla 5): solo CC0, MIT, Apache 2.0 o GPL. Ninguna fila CC-BY ni CC-BY-SA, salvo que D19 esté aprobada.
4. **`referencias/` no está en git:** `git ls-files referencias | wc -l` debe dar 0. Tampoco `diseno/referencias/privadas/`.
5. **Código GPL solo en `blender/`:** `grep -rl --exclude-dir={capturas,salida,referencias,__pycache__,.godot} -i 'mpfb' godot/` solo puede dar comentarios. `grep -rn 'import mpfb\|from mpfb\|bl_ext' godot/` debe dar 0.
6. **Cabecera de licencia en `blender/`:** cada `blender/*.py` dice en su cabecera que es GPL-3.0 o posterior (`grep -L 'GPL' blender/*.py` debe salir vacío).
7. **Fuentes:** si el tema de la interfaz usa una fuente que no es la de Godot, tiene fila y su archivo de licencia (OFL) al lado.
8. **Animaciones de prueba dentro del build** (paso 5.1, D12): fila de Quaternius con «dónde se usa» actualizado a la ruta dentro de `godot/`.
9. **Los personajes exportados:** el README dice que el usuario puede usarlos sin condiciones (los datos son CC0 y la salida del programa no hereda la MIT).
10. **Nombre:** «GameMolde» sigue siendo provisional. Antes de publicar, el responsable confirma el nombre (regla 3; D28). Buscar si existe otro programa con ese nombre es tarea del responsable (pide red).
11. **Godot en el build:** el programa exportado incluye el motor (MIT) y bibliotecas de terceros (FreeType, mbedTLS y otras). Sus licencias piden reproducir el aviso. Se cumple con el 7.3b.

`godot/datos/LICENCIA.txt`: 5 líneas. Qué son los datos, de dónde salen (MakeHuman, CC0) y que las formas propias (cara anime y Fase 6) son CC0. Como es un archivo nuevo dentro de `datos/` que el manifiesto no lista, no afecta a los `sha256`.

### 7.3b — Diálogo «Licencias»

```gdscript
# godot/app/licenses_dialog.gd
extends AcceptDialog
## Diálogo «Licencias»: programa, material de terceros y avisos de Godot.

const PROGRAM_LICENSE := "res://LICENCIA_PROGRAMA.txt"   # copia de LICENSE
const CREDITS := "res://CREDITOS.txt"                    # copia de CREDITOS.md

## Texto completo, en tres bloques con título. Función pura: se puede probar sin ventana.
static func build_text(program: String, credits: String) -> String
```

Algoritmo de `build_text`:
1. Bloque «GameMolde»: versión (`application/config/version`) y el texto de `program`.
2. Bloque «Material de terceros»: el texto de `credits`.
3. Bloque «Godot Engine»: `Engine.get_license_text()`.
4. Bloque «Bibliotecas incluidas en Godot»: para cada elemento de `Engine.get_copyright_info()` (lista de diccionarios con `name` y `parts`; cada parte tiene `copyright` y `license`), una línea con el nombre, los titulares y el nombre de la licencia. Después, para cada clave de `Engine.get_license_info()` (diccionario nombre → texto), el texto completo.
5. El diálogo muestra el resultado en un `RichTextLabel` o `TextEdit` de solo lectura con barra de desplazamiento.

Decisión técnica: `LICENSE` y `CREDITOS.md` están fuera de `godot/`, así que no entran en el build. Se copian a `godot/LICENCIA_PROGRAMA.txt` y `godot/CREDITOS.txt` y se añaden al filtro de inclusión del preset (`datos/*, *.txt`). La prueba comprueba que las copias son idénticas a los originales, para que no se queden viejas.

## 6. Prueba

`pruebas/godot/probar_licencias.gd` (sin ventana; se lanza con `--path godot` porque usa `res://`, convención A6):

| Comprobación | Límite |
| --- | --- |
| `build_text` contiene `MIT`, `MakeHuman`, `Quaternius`, `Godot Engine` y `FreeType` | Las 5 |
| `godot/LICENCIA_PROGRAMA.txt` es idéntico a `LICENSE`; `godot/CREDITOS.txt`, a `CREDITOS.md` | Mismo `sha256` |
| Longitud del texto | > 10.000 caracteres (los avisos de Godot son largos) |
| Cada fila de `CREDITOS.md` tiene 5 columnas y una licencia de la lista admitida | 0 filas malas |
| Dentro del build (ampliar la autoprueba de A2b): `FileAccess.file_exists("res://CREDITOS.txt")` | `true` |

**Que la prueba detecta el fallo:** añadir una fila a `CREDITOS.md` con licencia `CC-BY-NC` → debe fallar. Cambiar una letra de `LICENSE` → debe fallar por copia distinta. Deshacer los dos cambios.

## 7. Trampas conocidas

- `Engine.get_license_text()`, `Engine.get_copyright_info()` y `Engine.get_license_info()` existen en Godot 4 (documentados en la 4.4). La forma exacta de los diccionarios: comprobarla imprimiendo el primer elemento antes de escribir el bucle.
- En `--headless` estas funciones devuelven lo mismo: la prueba no necesita ventana.
- No pegues los textos de licencia de Godot en un archivo del repositorio: se leen del motor, así siempre corresponden a la versión usada.
- Una licencia «gratis para uso personal» o «royalty free» **no** es CC0. Si una fila dice algo así, es «mal».
- Los `.glb` de Quaternius: comprobar que la fila enlaza a la página donde consta CC0. No se puede abrir la red sin permiso: si hay duda, se pregunta.

## 9. Si te atascas

- Si encuentras un archivo de terceros sin origen claro: **para**. No lo borres ni le inventes una licencia. Da la ruta y pregunta.
- Si un punto de la lista sale «mal» y arreglarlo exige quitar un asset que se usa: es decisión del responsable. Anótalo en `ruta/DECISIONES.md` como propuesta.
- No uses la red para «confirmar» licencias sin permiso (regla 1).
