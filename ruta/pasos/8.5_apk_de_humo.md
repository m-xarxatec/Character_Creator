# 8.5 — APK de humo: abrir en Android y medir

> Fase 8, paso **opcional** (D21). Si D21 = b, este paso se hace como 15.1. Depende de A2 (los datos dentro del `.pck`) y 7.1.
> No es una versión para usuarios. Es un instrumento de medida: sus números deciden D20 y condicionan el diseño del estudio (Fase 10).

## 1. Objetivo y «Hecho cuando»

**Objetivo:** saber con números reales si el núcleo cabe en un móvil de gama media.

**Hecho cuando:** el APK se instala en un aparato Android real, muestra el maniquí, y el archivo `ruta/medidas/8.5_android.md` tiene las 8 medidas del §6 con el modelo de aparato y su versión de Android.

## 5. Diseño

### 5.1 Herramientas (las instala el responsable; piden red: regla 1)

1. JDK 17 (OpenJDK).
2. SDK de Android: `platform-tools` (trae `adb`), `build-tools` y una plataforma. Las versiones exactas que pide Godot 4.7: **NO VERIFICADO**; están en su documentación («Exporting for Android»). Copiarlas de ahí, no de esta ficha.
3. En Godot: Editor → Configuración del editor → Exportar → Android: ruta del SDK y del JDK.
4. Almacén de claves de depuración: `keytool -keyalg RSA -genkeypair -alias androiddebugkey -keypass android -keystore debug.keystore -storepass android -dname "CN=Android Debug,O=Android,C=US" -validity 9999 -deststoretype pkcs12`. Se guarda **fuera del repositorio**. Su ruta va en la configuración del editor, no en `export_presets.cfg`.
5. En el móvil: activar «Opciones de desarrollador» y «Depuración USB». `adb devices` debe listar el aparato.

### 5.2 Preset «Android»

- Arquitectura: solo `arm64-v8a`. Motivo: es la de todos los móviles de gama media actuales y reduce el APK a la mitad.
- Compilación con Gradle: **desactivada** (plantilla ya compilada). Motivo: sin plugins no hace falta.
- Nombre de paquete: `org.gamemolde.humo` (provisional; el definitivo se decide en 15.7).
- Permisos: ninguno.
- Renderizador: el de móvil por defecto (Mobile). No forzar nada.
- Mismos filtros de recursos que Linux (`datos/*, *.txt`).
- *Custom features*: `banco_medidas`.

### 5.3 Medidor dentro del programa

Las pruebas de `pruebas/godot/` no viajan en el APK. Hace falta una versión mínima dentro de la app:

```gdscript
# godot/app/bench.gd
extends Node
## Banco de medidas dentro del programa (paso 8.5). Se activa con la etiqueta de exportación "banco_medidas"
## o con `-- --medir`. Muestra las medidas en pantalla y las guarda en user://medidas.txt.

const WARMUP := 60
const FRAMES := 600

## Lanza todas las medidas, una tras otra. body_view: la vista ya cargada.
func run(body_view: Node) -> void
## Estadísticas de una lista de tiempos en ms: {media, p50, p99, max}.
static func stats(times_ms: PackedFloat32Array) -> Dictionary
```

Medidas, en este orden (cada una imprime `MEDIDA <nombre>: <valor>`):

1. `arranque_ms`: `Time.get_ticks_msec()` al terminar `_ready` de `main.gd` (cuenta desde que arranca el motor).
2. `carga_especie_ms`: tiempo de `SpeciesData` (hoy 695 ms en PC).
3. `sha256_ms`: tiempo de la comprobación del `sha256` (medirla aparte: `PLATAFORMAS.md` §2, trampa 6).
4. `reposo_ms`: 600 fotogramas con el maniquí quieto → media y p99 (coste de dibujar).
5. `arrastre_normal_ms`: 600 fotogramas moviendo `muscle` de 0 a 1 y vuelta con el preset de personaje nuevo → media y p99. Es el caso real.
6. `arrastre_peor_ms`: lo mismo con todas las formas a 0,3 (el caso de `probar_rendimiento.gd`).
7. `update_ms`: tiempo de CPU de `CharacterUpdater.update` (con `Time.get_ticks_usec()` alrededor de la llamada), media de 100 llamadas.
8. `memoria`: `OS.get_static_memory_usage()`, `Performance.get_monitor(Performance.RENDER_VIDEO_MEM_USED)` y `Performance.get_monitor(Performance.RENDER_BUFFER_MEM_USED)`, antes y después de cargar la especie.
9. Datos del aparato: `OS.get_model_name()`, `OS.get_version()`, `RenderingServer.get_video_adapter_name()`, `RenderingServer.get_current_rendering_method()`, tamaño de la ventana.

Los tiempos de fotograma se toman como en `probar_rendimiento.gd`: diferencia de `Time.get_ticks_usec()` entre fotogramas, con `DisplayServer.window_set_vsync_mode(DisplayServer.VSYNC_DISABLED)`. En Android la sincronización vertical puede no desactivarse (**NO VERIFICADO**): si la media sale clavada en 16,67 ms, anotar «limitado por la pantalla» y fiarse de `update_ms` y del p99.

### 5.4 Instalar y leer

```sh
godot --headless --path godot --export-debug "Android" ../build/android/gamemolde-humo.apk
ls -l build/android/gamemolde-humo.apk                      # MEDIDA tamaño del APK
adb install -r build/android/gamemolde-humo.apk
adb logcat -c && adb shell monkey -p org.gamemolde.humo 1    # lo arranca
adb logcat -s godot:V | grep -E 'MEDIDA|ERROR|AUTOPRUEBA'    # las medidas
adb shell dumpsys meminfo org.gamemolde.humo | grep -E 'TOTAL|Graphics|Native Heap'   # memoria vista por el sistema
```

## 6. Prueba

Las medidas se comparan con el presupuesto de `RENDIMIENTO.md` §2. En este paso **no hay límites que hagan fallar nada**: se anota y se decide.

| Medida | Presupuesto de Android (PROVISIONAL) | Qué decide |
| --- | --- | --- |
| Tamaño del APK | ≤ 80 MB | Si recortar animaciones (D12) |
| `arranque_ms` + `carga_especie_ms` | ≤ 6.000 ms | Si hace falta pantalla de carga o caché |
| `sha256_ms` | ≤ 300 ms | Si se comprueba solo en depuración |
| `reposo_ms` media / p99 | ≤ 16,7 / 33 ms | Si el contorno se simplifica en móvil |
| `arrastre_normal_ms` media / p99 | ≤ 33 / 66 ms | **D20: deslizadores en Android** |
| `arrastre_peor_ms` | Solo se anota | — |
| `update_ms` | ≤ 10 ms | Qué se recalcula al arrastrar (`RENDIMIENTO.md` O1) |
| Memoria total (`dumpsys`, línea TOTAL) | ≤ 500 MB | Si hacen falta formas dispersas (16.4) |

Además: la autoprueba de A2b dentro del APK (`AUTOPRUEBA: TODO BIEN` en `logcat`) confirma que `datos/` se lee desde el APK.

**Que la prueba detecta el fallo:** en PC, lanzar el medidor (`godot --path godot -- --medir`) y comparar `arrastre_peor_ms` con el resultado de `probar_rendimiento.gd` en la misma máquina: deben diferir menos de un 20 %. Si no, el medidor mide mal.

## 7. Trampas conocidas

- Sin plantillas de exportación de Android o sin SDK configurado, `--export-debug` falla con un mensaje claro. No es un fallo del proyecto.
- Godot en Android **no pasa argumentos de línea de comandos** de forma sencilla: por eso el medidor se activa con la etiqueta `banco_medidas` del preset (`OS.has_feature("banco_medidas")`), no con `--medir`.
- `print()` sale en `logcat` con la etiqueta `godot`.
- Primer arranque tras instalar: Godot compila shaders y puede tardar el doble. Medir el **segundo** arranque y anotar los dos.
- El móvil reduce la potencia cuando se calienta: medir en frío, con batería por encima del 50 % y sin modo ahorro. Anotar la temperatura si el aparato la da.
- `RENDER_BUFFER_MEM_USED` y `RENDER_VIDEO_MEM_USED` pueden dar 0 en algunos controladores móviles (**NO VERIFICADO**). Para eso está `dumpsys meminfo`.
- No subas a git `debug.keystore` ni rutas de claves (`grep -n -i 'keystore\|password' godot/export_presets.cfg`).
- Si el aparato no tiene Vulkan, Godot puede abrir con Compatibility o no abrir. Anotar `get_current_rendering_method()`.
