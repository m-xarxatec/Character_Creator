## 1. Objetivo y «Hecho cuando»

Un solo archivo de la interfaz decide qué hay en cada plataforma, y en Android lo que no hay **no se crea**.

2. Con la plataforma simulada «android», la ventana no tiene botón Exportar, Ctrl+E, diálogo `.glb`, «Probar huesos»,
   lista de animaciones ni informe; sí Abrir y Guardar.
3. En PC la ventana tiene los mismos botones, textos y orden que antes del paso.
4. Fuera de `platform.gd` nadie pregunta la plataforma.

## 5. Diseño

Decisiones (una frase cada una):

- **Dos perfiles, `pc` y `android`** (cualquier móvil cuenta como `android`), porque son los únicos de la tabla.
- **Función desconocida = `false` con `push_warning`:** una errata nunca enseña algo de más.
- **`static var simulated`** para construir la ventana entera como Android en una prueba, sin depender de argumentos de
  Godot sin comprobar.
- **Lo que no hay no se crea** (no se oculta): ni nodo ni atajo.
- **Solo se corta la interfaz:** `BodyView.start_export` sigue, porque el Estudio hornea con él.
- **`alta_resolucion` es un número** (`max_image_side`): 8192 en PC y 4096 en Android.

### 15.2a — `platform.gd` (`extends RefCounted`, sin `class_name`, como el resto de `app/`)

```gdscript
const PC := "pc"
const ANDROID := "android"
const FEATURES := {  # función → plataformas que la tienen
	"editar_cuerpo": [PC, ANDROID], "editar_cara": [PC, ANDROID],  # Android: D20, a falta de medir (15.1)
	"estudio": [PC, ANDROID], "abrir_proyecto": [PC, ANDROID], "guardar_proyecto": [PC, ANDROID],
	"exportar_glb": [PC], "exportar_vrm": [PC], "banco_de_pruebas": [PC], "importar_pieza": [PC],
	"escultura": [PC], "packs_usuario": [PC]}
const MAX_IMAGE_SIDE := {PC: 8192, ANDROID: 4096}
static var simulated := ""                      # solo pruebas; "" = la plataforma real
static func current() -> String                 # simulated; si no, ANDROID con OS.has_feature("mobile") o ("estudio")
static func is_mobile() -> bool                 # current() == ANDROID
static func can(feature: String, platform := "") -> bool          # "" = current()
static func max_image_side(platform := "") -> int                 # plataforma desconocida: la de ANDROID
```

### 15.2b — La ventana

1. `body_actions.setup`: «Probar huesos», lista de animaciones y de expresiones solo con `banco_de_pruebas`; botón
   Exportar, su atajo y `file_dialog` solo con `exportar_glb`. `message` se crea siempre (lo usan Guardar y Abrir):
   separar `_add_dialogs`. `set_pose_t` y `set_animation` salen si su control es `null`.
2. Nombres de nodo (la prueba los busca): `Exportar`, `ProbarHuesos`, `Animacion`, `Expresion`.

## 7. Trampas conocidas

- La prueba y `main.gd` deben cargar **el mismo** `platform.gd` (misma ruta) para compartir `simulated`; si el caso
  Android sale como PC, es esto. Volver a `""` al acabar.
- `simulated` se pone **antes** de crear la ventana: todo se decide en `_ready`.
- Los nodos se crean por código: `find_child(…, true, false)`; con `owned = true` no encuentra ninguno.
- `export_to` y `view.export_glb` los usan las pruebas de PC y la autoprueba: no se borran.
- `--feature estudio` como argumento: **NO VERIFICADO**; no se usa (la etiqueta se pondrá en el preset, 15.1).
