# 7.2 — README con capturas, vídeo y créditos

> Paso del MVP (Fase 7). Depende de 7.1 (hay algo que descargar) y de 7.3 si se quiere cerrar el apartado de licencias de una vez (se pueden hacer en cualquier orden).

## 1. Objetivo y «Hecho cuando»

**Objetivo:** que una persona que no conoce el proyecto sepa, leyendo solo el `README.md`, descargar el editor, crear un personaje y usarlo en Godot.

**Hecho cuando:**
- El README tiene las 7 secciones del §5, en ese orden.
- Todos los enlaces y rutas del README existen (lo comprueba la prueba del §6).
- Una persona ajena sigue la sección «Usar el personaje en Godot» en un proyecto vacío y ve el personaje animado. Esto lo comprueba el responsable con alguien, o él mismo en `pruebas/godot_vacio/`.

## 2. Nivel de modelo

**Simple.** Es redacción con una estructura dada. Las capturas las elige el responsable.

## 3. Contexto mínimo

- `README.md` (48 líneas) y `CREDITOS.md`.
- `CLAUDE.md`, tabla «Reglas del personaje exportado».
- `pruebas/fase_3/probar_importador.sh`, solo la cabecera (cómo se importa el `.glb` con su BoneMap).
- `godot/addons/creador/glb_exporter.gd`, cabecera (qué archivos escribe).

## 4. Archivos

- **Se tocan:** `README.md`.
- **Se crean:** `docs/capturas/` con 3 o 4 PNG **elegidos por el responsable** y, si lo graba, un vídeo corto o GIF.
- **No se toca:** `CREDITOS.md` (es del 7.3), código, `PLAN.md` salvo el registro.

## 5. Diseño

Secciones del README, en este orden. Frases cortas; nada de jerga sin explicar.

1. **Qué es** (3 líneas) + una captura del editor.
2. **Descargar y abrir.** Enlace a la página de versiones de GitHub. Linux: descomprimir, `chmod +x`, doble clic. Requisito: tarjeta gráfica con Vulkan. (El apartado de Windows lo añade la ficha 8.4.)
3. **Crear un personaje en 5 pasos:** elegir zona → mover deslizadores → Deshacer si hace falta → «Probar huesos» → «Exportar».
4. **Usar el personaje en Godot.** Pasos numerados, uno por línea:
   1. Copiar el `.glb` y el `.tres` a tu proyecto.
   2. Seleccionar el `.glb` → pestaña Importar → Avanzado → nodo `Skeleton3D` → Retarget → Bone Map → nuevo `BoneMap` con perfil `SkeletonProfileHumanoid` → Reimportar. (Copiar los nombres exactos de menú de `probar_importador.sh` y de lo decidido en el 5.7; si el 5.7 aprobó exportar con los ejes del perfil, decir que no hace falta «Overwrite Axis».)
   3. Para qué sirve el `.tres`: es el material toon; se arrastra a la malla. Sin él, el personaje se ve con el material simple del `.glb`.
   4. Los puntos de anclaje: `socket_hand_r`, `socket_hand_l`, `socket_back`, `socket_hip`. Un ejemplo de 3 líneas de GDScript para colgar un objeto.
   5. Animaciones: sirve cualquier animación humanoide; enlace a la biblioteca de Quaternius (CC0).
5. **Qué sale en el `.glb`** (tabla corta copiada de las reglas de `CLAUDE.md`: metros, Y arriba, pose T o la decidida en D11, 53 huesos con nombres del perfil humanoide, 4 pesos).
6. **Para desarrolladores.** Requisitos: Godot 4.7.2, **Git LFS** (sin él `cuerpo.glb` es un archivo de texto de 130 bytes y el editor no carga), Blender 5.2 + MPFB solo para regenerar `datos/`. Cómo lanzar el editor y las pruebas (una línea cada uno). Tabla de carpetas (la actual, con `godot/datos/` si A2 está hecho).
7. **Licencias y créditos.** MIT el programa; CC0 los datos y **los personajes que crees** (decirlo claro: «los personajes que exportas son tuyos; puedes usarlos en juegos comerciales»); GPL solo `blender/`. Enlace a `CREDITOS.md`.

Quitar del README actual: «Estado: en construcción. Todavía no hay nada que ejecutar» y «Blender 4.2 o superior» (el proyecto fija 5.2.2).

**Capturas.** No las elijas ni las describas tú. Genera candidatas con las pruebas que ya guardan capturas (por ejemplo `probar_estilo.gd` y la del banco, cada una con `--salida=<carpeta>` si lo admite) y da las rutas al responsable. Las del editor (ventana completa) las hace el responsable con la tecla de captura del sistema.

**Vídeo.** Lo graba el responsable (30–60 s: mover deslizadores, probar huesos, exportar, abrir en Godot). En el README va como enlace o GIF de menos de 5 MB. No subir vídeos grandes al repositorio.

## 6. Prueba

Script pequeño `pruebas/fase_7/probar_readme.sh` (se crea en este paso):

| Comprobación | Límite |
| --- | --- |
| Cada ruta entre comillas invertidas del README que empiece por una carpeta del repositorio existe (`test -e`) | 0 rutas rotas |
| Cada imagen enlazada (`![…](ruta)`) existe y pesa menos de 1 MB (5 MB si es GIF) | 0 fallos |
| El README contiene las cadenas `Git LFS`, `BoneMap`, `socket_hand_r`, `MIT`, `CC0` | Las 5 |
| El README no contiene `en construcción` | 0 apariciones |

**Que la prueba detecta el fallo:** renombrar una captura y lanzar el script: debe decir cuál falta.

## 7. Trampas conocidas

- Los nombres de menú de Godot cambian con el idioma del editor. Escribirlos en inglés (como salen por defecto) y entre comillas.
- El botón «Download ZIP» de GitHub **no incluye los archivos de Git LFS**. Decirlo en «Para desarrolladores»: hay que clonar con `git lfs` instalado.
- No prometas en el README nada que el MVP no haga (cara, pelo, ropa). Eso está en `IDEAS.md`.
- Regla 5: cualquier imagen del README debe ser nuestra (captura del programa). Nada de `referencias/`.
