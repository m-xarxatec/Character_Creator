# 7.1 — Build de Linux

> Paso del MVP (Fase 7). Depende de A2 (los tres subpasos) y de que las Fases 4, 5 y 6 estén cerradas.
> La parte «decidir dónde vive `datos/`» del PLAN ya está resuelta en A2 (D5). El build de Windows es la Fase 8.

## 1. Objetivo y «Hecho cuando»

**Objetivo:** un ejecutable de Linux que funciona sin Godot instalado y sin el repositorio.

**Hecho cuando:**
- `build/linux/gamemolde.x86_64`, copiado a una carpeta vacía fuera del repositorio, imprime `AUTOPRUEBA: TODO BIEN` con `-- --autoprueba`.
- El `.glb` que escribe esa autoprueba pasa `probar_glb.gd`.
- El responsable lo abre a mano, mueve un deslizador y exporta.

## 2. Nivel de modelo

**Medio.** El preset de exportación ya existe (A2c). Lo nuevo son las plantillas de exportación (instalación con red: la hace el responsable) y comprobar el programa fuera del repositorio.

## 3. Contexto mínimo

- `ruta/pasos/A2_datos_en_el_proyecto.md`, §5 (A2b y A2c) y §7.
- `godot/export_presets.cfg` (creado en A2c).
- `godot/project.godot` (15 líneas).

## 4. Archivos

- **Se tocan:** `godot/export_presets.cfg` (desde el editor de Godot, no a mano), `godot/project.godot` (una línea: `config/version`), `.gitignore` (una línea: `build/`).

## 5. Diseño

1. **Plantillas de exportación (lo hace el responsable; pide red).** En el editor de Godot: Editor → Administrar plantillas de exportación → Descargar e instalar (versión 4.7.2 estable). Comprobación: existe `~/.local/share/godot/export_templates/4.7.2.stable/linux_release.x86_64`.
2. **Versión del programa.** En `project.godot`, sección `[application]`: `config/version="0.1.0"`. El diálogo «Acerca de» y el nombre del `.zip` la leen con `ProjectSettings.get_setting("application/config/version")`.
3. **Preset «Linux»** (el responsable, en Proyecto → Exportar):
   - Arquitectura: `x86_64`.
   - «Incrustar PCK»: **activado**. Motivo: un solo archivo que repartir; el usuario no puede separar el ejecutable de sus datos.
   - Pestaña Recursos: «Exportar todos los recursos» y filtro de inclusión `datos/*` (ya puesto en A2c).
   - Ruta de exportación: `../build/linux/gamemolde.x86_64`.
4. **`.gitignore`:** añadir `build/`.
5. **Script de la prueba** (`pruebas/fase_7/probar_build_linux.sh`):
   ```sh
   #!/bin/sh
   # 7.1: exporta el build de Linux y lo prueba en una carpeta vacía, fuera del repositorio.
   # Uso: pruebas/fase_7/probar_build_linux.sh 2>&1 | grep -E 'AUTOPRUEBA|RESULTADO|MEDIDA|ERROR'
   set -e
   here=$(cd "$(dirname "$0")" && pwd)
   root=$(cd "$here/../.." && pwd)
   mkdir -p "$root/build/linux"
   (ulimit -v 4000000; timeout 600 godot --headless --path "$root/godot" --export-release "Linux" "$root/build/linux/gamemolde.x86_64")
   tmp=$(mktemp -d)
   cp "$root/build/linux/gamemolde.x86_64" "$tmp/"
   cd "$tmp"
   echo "MEDIDA tamaño del build (bytes): $(stat -c %s gamemolde.x86_64)"
   (ulimit -v 4000000; timeout 120 ./gamemolde.x86_64 --headless -- --autoprueba)
   echo "RESULTADO carpeta de la prueba: $tmp"
   ```
6. **Comprobar el `.glb` de la autoprueba.** La autoprueba escribe en `user://` (en Linux: `~/.local/share/godot/app_userdata/GameMolde/autoprueba.glb`). Copiar ese `.glb` y su `.tres` adonde los espera `probar_glb.gd` (su cabecera dice la ruta) y lanzarla.
7. **Medir el arranque** (con ventana, lo lanza el responsable): `time ./gamemolde.x86_64 -- --autoprueba`. Anotar en el registro. Presupuesto: `RENDIMIENTO.md` §2 (≤ 3 s en PC modesto).

## 6. Prueba

| Comprobación | Límite |
| --- | --- |
| `probar_build_linux.sh` | Imprime `AUTOPRUEBA: TODO BIEN` |
| `.glb` de la autoprueba con `probar_glb.gd` | `TODO BIEN` |
| En la carpeta de la prueba solo hay un archivo | 1 (`gamemolde.x86_64`) |
| Tamaño del build | Se anota. Esperado: 80–110 MB (plantilla de unos 70 MB + `datos/` + animaciones). PROVISIONAL |
| Todas las pruebas sin ventana de `pruebas/godot/` | Siguen pasando |

**Que la prueba detecta el fallo:** quitar el filtro `datos/*` del preset y repetir: debe imprimir `AUTOPRUEBA: FALLO`. Volver a ponerlo.

## 7. Trampas conocidas

- `--export-release` sin plantillas instaladas falla con un mensaje sobre «export templates». No es un fallo del proyecto: falta el punto 1.
- El nombre del preset distingue mayúsculas: `"Linux"`, igual que en `export_presets.cfg`.
- La primera vez tras clonar hay que importar: `(ulimit -v 4000000; timeout 300 godot --headless --path godot --import)`.
- `export_presets.cfg` puede guardar rutas de claves y contraseñas en la sección de Android. Hoy no hay preset de Android; cuando lo haya, las credenciales van en `.godot/export_credentials.cfg` (que ya está fuera de git por `.godot/`). Antes de cada commit: `grep -n -i 'password\|keystore' godot/export_presets.cfg` debe salir vacío o con valores vacíos.
- Que el proyecto `pruebas/godot/` **no** entre en el build: es otro proyecto, no está bajo `godot/`. Comprobación: el build no contiene `UAL1_Standard` salvo que el 5.1 lo haya copiado dentro a propósito (D12).
- Un ejecutable copiado puede perder el permiso de ejecución: `chmod +x gamemolde.x86_64`. Dentro de un `.zip` hecho con `zip` el permiso se conserva.
- El build exige una tarjeta con Vulkan (Forward+). En una máquina sin Vulkan el programa no abre ventana. El aviso va en el README (7.2); el renderizador se decide en el 5.13 y se fija con A7.

## 9. Si te atascas

- Si la autoprueba falla dentro del build pero pasa con `--main-pack` (A2c): **para** y enseña la línea de `FALLO`. No cambies el cargador.
- Si el build pasa de 150 MB: no recortes nada por tu cuenta; da la medida y la lista de lo que más pesa (`godot --headless --path godot --export-pack "Linux" x.pck` y `ls -l`).
- No instales las plantillas tú: requiere red (regla 1).
